# UI Redesign v2 - Frontend Implementation Plan

**Inputs (read first):** `docs/spec/proposed/ui-redesign-v2.md` (requirements, rules),
`docs/spec/proposed/ui-redesign-v2.openapi.yaml` (proposed endpoints),
`docs/product/decisions/2026-10-29-ui-redesign-v2.md` (decisions),
`docs/prototypes/finance-ui-v2/*.dc.html` (visual reference; layout, sections,
copy and tokens. Its numbers are sample data and must never be shipped).

**Rules that bind every task:** `AGENTS.md`; no fabricated data; every new panel
renders explicit loading / empty / partial / unavailable states; normal flows
call the Spring backend only (never the data-service); preserve existing
endpoint paths and DTO fields; no live provider calls in tests (MSW stubs);
Turkish UI copy; 44 px touch targets; real `<button type="button">`/`<a>`;
accessible names for charts (`role="img"` + label, plus a data table or text
equivalent where the data matters); charts via `recharts` (already a
dependency) loaded with `React.lazy` where heavy, or small hand-written SVG;
keep `npm run check:bundle` within budget.

**Do not** commit, push, or touch unrelated working-tree changes.

## Task F0 - Foundation (one agent, runs first)

Files owned: `frontend/src/index.css`, `frontend/src/components/LeftNav.tsx`,
`TopBar.tsx`, `frontend/src/App.tsx` (routes and page titles only), new
`frontend/src/api/redesign/*`, new `frontend/src/components/ui/PanelState.tsx`,
new `frontend/src/hooks/usePanelQuery.ts`, `frontend/src/test/handlers.ts`
(additive), new `frontend/src/components/CompareView.tsx` shell.

1. Tokens: move the dark theme to the v2 palette from the design (`Main.dc.html`
   helmet): page `#0E1015`, panels `#12141A`, borders `#1E222C`/`#232734`,
   text `#E7E9F0`, muted `#B4BACB`/`#9097A8`, accent `#2563EB`, link `#60A5FA`,
   Plus Jakarta Sans. Keep existing CSS variable names working (aliases) so
   untouched components keep rendering; do not break existing tests.
2. Shell: grouped left nav (Genel / Piyasa / Hisseler / Portföy) with the nine
   entries and titles from spec §2; top bar adds the BIST/ABD market toggle
   (state in a small context, persisted in `localStorage` with try/catch;
   internal value `ALL | BIST | US`, default `ALL` with neither button
   highlighted; pressing the active button again returns to `ALL`), notification bell with
   unread badge from the existing `GET /notifications/unread`, static profile
   chip. Routes keep their paths; add `/compare` (lazy `CompareView`).
   Screen titles per spec §2.
3. API layer `src/api/redesign/`: TypeScript types and zod schemas generated by
   hand from the OpenAPI file for every response (`DataStatus`, `Meta` base,
   all schemas), one typed function per endpoint using the existing axios
   client (`src/api/client.ts`, `http.ts`, `errors.ts` conventions), grouped in
   files by tag (portfolioAnalytics, riskAndStops, comparison, earnings,
   transactions, newsCalendar, watchlists, company, reports). Respect
   `scripts/check-api-boundaries.cjs`.
4. `usePanelQuery(fetcher, deps)` hook -> `{state: 'loading'|'ready'|'empty'|'partial'|'unavailable'|'notImplemented', data, error, reload}`; 404/501 -> `notImplemented`;
   `status` field mapped from the body. `PanelState` component renders the
   uniform message ("Veri alınamadı", "Henüz veri yok", "Kısmi veri: ...",
   skeleton) with a retry button.
5. MSW handlers for every new endpoint returning `UNAVAILABLE` by default plus
   small valid fixtures usable by view tests (clearly named `fixture*`, only in
   tests).
6. Tests for the hook, PanelState, nav/market toggle, and zod schemas against
   fixtures. Run: `npm run lint`, `npm run check:api-boundaries`, `npm test`,
   `npm run build`, `npm run check:bundle` (each is limited to 120 s; run
   individual test files with `npx vitest run <file> --config vitest.config.ts`
   when needed).

## Task F1..F6 - Views (parallel after F0, disjoint files)

Each task replaces the visual composition of its screen with the design,
keeps all existing working behavior and its tests green (update tests only
where the markup intentionally changed), adds the new sections as panels
backed by `src/api/redesign` + `usePanelQuery`, and shows `PanelState` when the
backend slice is not implemented. Existing real data (portfolios, holdings,
prices, ledger, watchlists, news, calendar) keeps coming from existing
endpoints/hooks.

| Task | Files owned | Design file |
|---|---|---|
| F1 Panel | `DashboardHome.tsx` (+ new `components/dashboard/*`) and its test | `Main.dc.html` |
| F2 Portföylerim | `PortfolioManagerView.tsx` (+ `components/portfolio/*`) | `Portfolio.dc.html` |
| F3 Compare + İzleme Listeleri | `CompareView.tsx` (+ `components/compare/*`), `WatchlistsView.tsx`, `components/watchlist/*` | `Compare.dc.html`, `Watchlist.dc.html` |
| F4 Haberler + Raporlar | `NewsFeedView.tsx`, `components/news/*`, `AiReportsView.tsx` (+ `components/reports/*`) | `News.dc.html`, `Reports.dc.html` |
| F5 İşlem Ekle + Kazanç Analizi | `TradingJournalView.tsx` and a new `EarningsAnalysisView.tsx` mounted at `/transactions` (App.tsx route element only) (+ `components/transactions/*`) | `Journal.dc.html`, `Transactions.dc.html` |
| F6 Şirket Analizi | `ChartWorkspace.tsx`, `components/research/*` | `Workspace.dc.html` |

F5 note: `/transactions` currently renders `TradingJournalView`; after F5 it
renders the earnings analysis, and `/journal` renders the add-transaction
screen. Existing journal functionality must stay reachable.
